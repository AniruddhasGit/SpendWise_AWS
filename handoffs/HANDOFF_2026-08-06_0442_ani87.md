### Defects worth carrying forward

Recorded because each one passed review and was caught only by running the thing:

- **`SW-ADR-149` — three admin capabilities that silently did nothing.** `SECURITY DEFINER`
  changes which *role* runs a function; it does not exempt that role from policies, and
  `FORCE ROW LEVEL SECURITY` subjects the owner to its own. Counting a person's expenses returned
  `(0, NULL)`; "who is signed in" returned `[]`; force-sign-out matched zero rows, returned **200**,
  and wrote an audit row saying *"signed user #2 out of 0 session(s)"*. **The general rule: in this
  system a privilege you cannot exercise fails silently and successfully. RLS does not raise, it
  filters.** Every cross-person capability needs a test asserting a non-empty, non-zero result for
  a *different* user.
- **`SW-ADR-146` — the day-one gate read the wall clock.** At midnight four assertions went red
  with no code change. The contract stated the value, the range, the rounding formula and three
  wrong answers, and never the date it is evaluated on. `gate.as_of` now exists.
- **`SW-ADR-147` — `--sw-border-strong` measured 2.36:1**, the same hex `SW-ADR-131` had already
  measured, found failing and darkened *for a different token*. A hand-maintained check measures
  what someone remembered to list.
- **A false green in a test**, caught by the test's own author: the admin detail pane renders its
  header before its figures, so `assert "Groceries" not in text` passed against a pane that had
  rendered nothing — on the exact boundary `CR-001` exists to hold.
