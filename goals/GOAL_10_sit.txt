DELIVERABLES
  1. SIT_TestCases.tsv - one row per positive case. Columns:
     case_id,bible_story,epic,title,case_type,persona,env,fixtures,preconditions,steps,
     expected,evidence_required,status
     - steps are numbered and unambiguous; expected is a single checkable outcome
     - fixtures name the exact seed rows the case depends on
     - evidence_required states what proves it: browser, API response, DB row, or audit row
  2. SIT_JourneyCases.tsv - one row per journey from docs/11, each listing the story cases
     it chains together.
  3. harness/README.md - how these rows become executable tests, and the rule that a case
     which cannot be run is a FAILURE, not an omission.

RULES

  - Never assert on a fixture. Every case must exercise the application.
  - Expected values are derived from the sources, not from what the code happens to do.
  - The day-one proof gets its own cases, including the RLS red-proof.
