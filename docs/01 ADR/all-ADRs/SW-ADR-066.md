## Context

Two independent descriptions of one schema always diverge, and the divergence is invisible until a migration assumes the wrong starting state. It is sharper for the RLS policies: if they live both in a migration and in a standalone security.sql, there are two places a policy can be defined and only one of them ever runs against the live database.

## Options considered

- A. Alembic authoritative; schema.sql and security.sql regenerated by a documented command, never hand-edited, with a test that fails if the committed files differ from a fresh regeneration.
- B. schema.sql is the design document.

## Decision

**A.**

## Consequences

- Drift that a test cannot see is drift that ships.
- This makes the GOAL_08 data-model package internally consistent by construction rather than by review.
